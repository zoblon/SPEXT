# Blitztext upstream review for SPEXT

Research date: 19 October 2026, 13:19 UTC. Research only; no recommended features implemented. Report language: English, with a German decision summary at the end.

## Recommendation

Adopt selected everyday improvements rather than merge the upstream redesign: **clipboard preservation, explicit spoken-to-written replacement rules, and conservative insertion fitting**. Keep SPEXT's recording engine, recording-quality checks, target-app safety, tested rewriting prompt, and fixed model choices. Evaluate local transcription as a separate, optional capability; the source does not establish that it is more accurate or faster than SPEXT's current API path on Tobi's hardware and vocabulary.

The big update is real and released. The 2 October reference note inside SPEXT is now stale. Blitztext has become a substantially different local-first application, not a small maintenance update.

## 1. Clipboard restoration: highest immediate return

Upstream snapshots every item/type, offers the transcript via a pasteboard data provider, waits for reads and a quiet period, and only restores while its own `changeCount` remains current. It uses a minimum hold of 1 second, 0.5-second quiet period, 5-second no-read timeout and 15-second upper bound. It also sets current-host-only and standard transient/concealed/generated markers. This is a much stronger approach than a fixed short timer. [Implementation](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/Services/ClipboardPasteService.swift#L11-L97), [timing and ownership logic](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/Services/ClipboardPasteService.swift#L193-L265), [existing tests](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/Tests/ClipboardRestoreTests.swift#L13-L88).

SPEXT currently clears the clipboard, writes the transcript, waits 80 ms, checks the original target PID and clipboard change count, then posts Cmd+V. It intentionally leaves the transcript available if Accessibility or target checks fail. [SPEXT baseline](https://github.com/zoblon/SPEXT/blob/0232010bd24011936dae09ffc5c267c1bc4d0eee/SPEXT/Services/PasteService.swift#L25-L50).

Adapt restoration *inside that existing guard*. A blocked paste should leave SPEXT's manual-copy fallback available; another user copy must win. A pasteboard read is a heuristic, not proof the target field accepted text: clipboard watchers can read too, which upstream itself acknowledges. Verify normal fields and slow apps, rich/multiple clipboard items, clipboard permission denial, no focused field, app switching, another user copy, consecutive dictations, and quit. Do not present a synthetic Cmd+V event as confirmed insertion.

## 2. Deterministic replacements: supplement existing keyword hints

SPEXT already has a maintained custom-word list; it sends filtered/deduplicated `keywords[]` to GPT Transcribe. This is a recognition hint, not an exact postprocessing guarantee. [Current keyword handling](https://github.com/zoblon/SPEXT/blob/0232010bd24011936dae09ffc5c267c1bc4d0eee/SPEXT/Services/TranscriptionService.swift#L91-L118).

Upstream adds explicit `spoken`/`written` pairs, escaped whole-word matching, flexible spaces/hyphens and longer-match-first ordering. Adopt that concept first. Keep the original recognized text recoverable and apply rules to the transcript before rewriting, so the message model sees intended names. Reapplying replacements to model output requires separate consideration to avoid unintended edits. [Rule model and matching](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/Services/TranscriptPostProcessor.swift#L11-L78).

Do not enable its full cleanup pipeline wholesale: it can remove fillers, use fuzzy dictionary matching and normalize repetitions. Those are editorial decisions in a mode that SPEXT treats as direct dictation. Named-term correction can help but deserves a later corpus test with Tobi's actual German/English vocabulary. Cascading/overlapping explicit rules also need defined semantics; upstream's sequential replacements can match text produced by an earlier rule.

## 3. Cursor fitting: local rules, tightly bounded

Upstream reads the focused text field using AX, excludes secure-text subroles, keeps up to 2,000 characters before and 600 after the selection, and adjusts only insertion boundaries using string rules. Model access to field context is a separate setting and defaults off. The reader obtains the field value before slicing; these limits are retained-context limits, not a guarantee it never reads a longer field. [Reader](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/Services/FocusedFieldReader.swift#L19-L67), [insertion logic](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/Services/InsertionFitter.swift#L3-L33), [defaults](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/Features/Workflows/WorkflowProtocol.swift#L140-L151).

SPEXT currently appends an unconditional trailing space. Boundary-aware spacing is valuable, especially for inserting inside a sentence. Start with spaces and duplicate punctuation; consider capitalization later, respecting German nouns, Sie/Ihr, English “I”, brand casing, code, URLs, lists and quoted text. Keep SPEXT's existing » « normalizer. If the field or caret moved during transcription, use conservative fallback formatting. Upstream snapshots at recording start and fits at completion; PID equality alone cannot establish snapshot freshness. [Upstream snapshot](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/App/AppState.swift#L799-L822), [completion](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/App/AppState.swift#L695-L708), [SPEXT trailing space](https://github.com/zoblon/SPEXT/blob/0232010bd24011936dae09ffc5c267c1bc4d0eee/SPEXT/AppState.swift#L682-L707).

Per-app modes are a separate useful convenience if Tobi routinely uses the wrong hotkey in Mail versus other apps. Bundle-ID rules are simpler than website detection. Upstream website rules inspect AX browser URLs, match subdomains and take precedence over app rules; explicit mode shortcuts remain explicit. This adds browser compatibility and privacy surface. It is not needed for the three core improvements. [Mode resolution](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/App/AppState.swift#L361-L390).

## 4. Local transcription and Apple Intelligence: evaluate separately

Blitztext now transcribes locally using FluidAudio/Parakeet Ultra or WhisperKit. Its source has model availability checks, downloads, installation validation, shared load tasks and a slow-Core-ML-preparation message. Dependencies are pinned: FluidAudio 0.17.4, ArgmaxOSS 0.18.0 and Sparkle 2.8.1. [Dependency configuration](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/project.yml#L23-L32), [Parakeet lifecycle](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/Services/ParakeetTranscriber.swift#L65-L150), [local dispatch/preparation](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/Services/LocalTranscriptionService.swift#L362-L410).

Preserve SPEXT's recorder and introduce a transcription backend boundary after its existing assembled M4A/quality result. Do not replace the capture engine to get a local model. Evaluate German, English and mixed terms, brand/client names, short messages, silence/noise, AirPods/Continuity capture, first run after update, warm run, memory and battery. Measure release-to-text latency and correction rate against the current cloud path. Upstream's own reported German error-rate improvement compares Parakeet Ultra with its previous Parakeet, not with GPT Transcribe or SPEXT; it cannot justify replacing SPEXT's model.

Apple Intelligence rewriting is another independent decision. Upstream checks macOS 26 availability and supports explicit provider routing. Local generation errors do not silently switch to a cloud provider. SPEXT already has a carefully specified GPT-6.1 Sol message prompt, low reasoning and truncated/empty-output handling. Retain that default until local rewriting passes the same factuality, language and tone examples. Multiple provider/model menus are not intrinsically an improvement for this lean app. [Upstream routing](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextShared/AI/TextRewriter.swift#L52-L104), [current SPEXT model](https://github.com/zoblon/SPEXT/blob/0232010bd24011936dae09ffc5c267c1bc4d0eee/SPEXT/Services/PolishService.swift#L9-L13).

Downloads and model attribution need their own UI/storage lifecycle, cancel/delete options and notices. Parakeet weights are documented as CC BY 4.0; Whisper/WhisperKit as MIT and FluidAudio as Apache 2.0 in upstream's notices. Verify the actual chosen artifact's current license before distributing it. [Upstream notices](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/THIRD_PARTY_NOTICES.md#L3-L13).

## 5. History: useful, but do not copy its security model

Upstream keeps at most 30 results, supports off/24 hours/7 days, prunes on lifecycle events, and defaults to 24 hours. It writes AES-GCM ciphertext. However, the misleadingly named `KeychainService` derives that file-encryption key from `IOPlatformUUID` (or hostname) and a hard-coded salt; it does **not** store a random history encryption secret in the Keychain. Another source comment saying the meeting key is “in the keychain” contradicts the actual implementation. [Retention and write](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/Services/TranscriptHistoryStore.swift#L4-L103), [actual derivation](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/Services/KeychainService.swift#L5-L20), [readable machine identifier](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/Services/KeychainService.swift#L49-L86).

Assessment: this prevents casual plaintext inspection but is a weak confidentiality boundary against software able to read the same machine identifier and file. Avoid describing it as Keychain-protected history. If persistent history is wanted in SPEXT, use a random AES-GCM key held as a Keychain secret, a SPEXT-owned directory, explicit retention/delete behavior, and visible save failures where recovery matters. Session-only recent results offer much of the retrieval benefit without an on-disk archive.

SPEXT already keeps the last result in memory and stores its API key in the real macOS Keychain. Its existing update-then-readback API-key save is preferable to upstream provider-store delete-then-add behavior, which removes the previous value before knowing the replacement save succeeded. [SPEXT Keychain save](https://github.com/zoblon/SPEXT/blob/0232010bd24011936dae09ffc5c267c1bc4d0eee/SPEXT/Services/KeychainService.swift#L32-L56), [upstream provider save](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextShared/AI/AIProvider.swift#L131-L139).

## Further features and smaller maintenance ideas

- **Audio-file import:** upstream converts in blocks to a temporary mono WAV, transcribes locally, optionally adds paragraphs, shows/copies the result and adds history. This is useful if voice files are common. Preserve source files and explicit copy/review rather than auto-pasting into whatever field is active. SPEXT's cloud service currently owns/deletes its input, making a temporary import copy essential. [Converter](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextShared/Audio/AudioFileConverter.swift#L32-L111), [controller](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/Features/AudioFile/AudioFileController.swift#L33-L85).
- **Automatic paragraphs:** small local NaturalLanguage tokenizer utility inserts blank lines after 45 words/four substantial sentences, without rewriting words. Upstream defaults it off. Reasonable optional convenience for long *direct* dictation; the message mode already produces paragraphs. It can make arbitrary rather than semantic breaks, so it should remain optional. [Implementation](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/Services/TranscriptParagraphService.swift#L3-L85).
- **Permission repair:** upstream includes a user-triggered `tccutil reset Accessibility <own bundle ID>` action. SPEXT already has a live checklist/setup flow; a compact repair action could help with stale grants after an installation change. Do not automatically reset permissions at launch. Roughly 0.5–1 day if the need recurs. [Action](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/Services/AccessibilityPermissionService.swift#L28-L45).
- **Crash-leftover cleanup:** upstream deletes its own named temporary dictations on startup. SPEXT handles normal/error-path deletion but writes UUID-only CAF/M4A temporary files; no launch orphan sweep was found. Move future temporary files into a SPEXT-specific per-session directory and clean only owned stale sessions. Never imitate a broad “delete all CAF/M4A in tmp” sweep. Roughly 0.5–1 day; privacy/storage hygiene, no transcript retention. [Upstream sweep](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/Services/AudioRecorder.swift#L15-L34), [SPEXT CAF creation](https://github.com/zoblon/SPEXT/blob/0232010bd24011936dae09ffc5c267c1bc4d0eee/SPEXT/Services/AudioRecorder.swift#L1232-L1245).
- **Updater:** upstream uses Sparkle with a configured own release feed/public key and excludes managed Jamf installs. Worth considering if SPEXT is being given to other people, less urgent for a single managed personal installation. A feed pointing at upstream would install the wrong product. [Service](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/Services/AppUpdateService.swift#L34-L92), [feed/key](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/project.yml#L14-L21).

## Do not copy wholesale

**Meeting recording and diarization** are real release features, but a separate product scope: long-lived audio, speaker models, persistent meeting records, summaries and recovery states. The source records 16 kHz PCM WAV in Application Support, preserves pending audio for retry/crash recovery and deletes it only after transcript storage succeeds. Thus “audio is deleted afterwards” is conditional, not “never persists.” The store has no analogous 24-hour/7-day automatic meeting retention policy in the inspected implementation. Summary routing uses the selected rewriting engine, so choosing an external provider changes the data path. This is not needed for a lean cursor-dictation app. [Processing/deletion](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextMac/Features/Meeting/MeetingController.swift#L215-L291), [persistent records](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/BlitztextShared/Meeting/MeetingStore.swift#L61-L100).

Also defer special anger/emoji modes, broad provider selection, browser-site automation, blanket fuzzy cleanup and upstream branding/layout. They expand settings, prompt QA, privacy behavior and support scope without proving an improvement in Tobi's current dictation workflow. Upstream source is MIT, while its name/logo/brand assets are reserved; copy useful implementation concepts/code with appropriate notices and SPEXT's identity. [License](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/LICENSE), [trademark terms](https://github.com/cmagnussen/blitztext-app/blob/0a72e2a1a0a1e474c0165f9a12aa01b42a3d928d/TRADEMARKS.md).

## German decision summary

Ja, das Update ist groß und inzwischen veröffentlicht: Seit 13. Oktober läuft Blitztext lokal; aktuell ist Version 1.14 vom 18. Oktober. Das heutige `main` enthält denselben Quellstand wie die Veröffentlichung.

Für SPEXT würde ich zuerst drei gezielte Dinge übernehmen: die Zwischenablage nach dem Einfügen wiederherstellen, feste Ersetzungsregeln ergänzen und Leerzeichen/Satzzeichen am Cursor vorsichtig anpassen. Das verbessert den täglichen Ablauf, ohne die App umzubauen.

Lokales Parakeet ist die interessanteste größere Ergänzung: offline diktieren, kein Audio-Upload. Dafür würde ich zunächst Erkennungsqualität und Wartezeit mit deinen echten deutschen/englischen Diktaten vergleichen. Die neue Blitztext-Version belegt noch nicht, dass dieser Weg SPEXTs aktuelle GPT-Transcribe-Strecke schlägt.

SPEXTs Aufnahme- und AirPods-Behandlung würde ich behalten. Auch Meetings, sämtliche KI-Anbieter und zusätzliche Spezialmodi würde ich nicht pauschal übernehmen. Bei der History gibt es einen konkreten Vorbehalt: Die Dateien sind verschlüsselt, der Schlüssel wird aber aus der auslesbaren Maschinenkennung abgeleitet. Für SPEXT wäre ein zufälliger Schlüssel im echten macOS-Schlüsselbund die bessere Grundlage.

Keine Funktionen umgesetzt. Der Bericht ist eine Empfehlung; Laufzeitverhalten und Modelle wurden nicht praktisch getestet.
